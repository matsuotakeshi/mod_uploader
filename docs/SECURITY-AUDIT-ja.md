# mod_uploader 3.2.0 セキュリティ監査・修正報告

監査日: 2026-10-24。比較元は `0772a53a1eae1af01f7ff78bbbca0e00a6dcaab3`（Portリビジョン4）、修正版はリビジョン5です。保存形式は4を維持します。

追加の問題が見つかったため修正しました。今回の検査は「脆弱性が一切ない」という保証ではありません。本番サービス・本番データを変更せず、FreeBSD上の専用保存領域とループバック接続の別Apacheで検証しました。

## 調査範囲

Apacheへの入力、multipart/メールの解析、アップロードの保存・世代管理、ダウンロード・削除の認証、パスワードとCSRF、テンプレート出力、共有メモリ・排他処理、移行ツール、Port設定を追跡しました。実際に構成されるApacheモジュールの43翻訳単位をClang Static Analyzerで解析しました。リポジトリの全行・全構成に対する形式検証ではありません。旧CGI、standalone、Java/Flashクライアント、Windows向け補助ツール等の全機能検証は含みません。

## 見つかった問題と修正

| 優先度 | 問題・影響 | 修正と確認方法 |
| --- | --- | --- |
| 高 | 満杯時に不正な投稿を送ると、入力検証より先に既存ファイルが削除される | 検証・文字コード変換・ハッシュ化を削除前に移動。比較元で保護付き既存ファイルの消失を実HTTPで再現し、修正版では保持を確認 |
| 高 | 容量調整と追加の排他区間が分かれ、一覧満杯時の挿入にも上限検査がない。共有領域外への書込みにつながる | 容量調整・保存・一覧追加を同じ書込みロックで保護。件数・合計サイズ・添字の検査と桁あふれ対策。実HTTPの16並行投稿とASan/UBSanでの境界検査 |
| 高 | 認証時に取得した情報と、後で開く・削除する同じIDのファイルが別世代になり得る | ID・index・時刻・サイズ・ダイジェスト・パスワードハッシュを排他区間で再比較。並行投稿のID生成も全保存アイテムの最大値から決定。比較関数の検査と並行HTTPでID重複なしを確認。認証競合の実攻撃再現までは未実施 |
| 高（構成依存） | メール投稿が接続元制限だけに依存する。保護された原本のサムネイルを直接取得できる | メールにもApache認証を必須化し、Port例では閉鎖。保護された原本の公開サムネイル取得を403で拒否。実HTTPで拒否を確認。画像生成そのものは無効の構成 |
| 中〜高 | タイムアウト時に他の処理の共有ロックを奪い、相互排他が崩れる | ロックを奪わず要求を失敗させる。実ロッククラスにタイムアウト判定を注入して検査。実際に300秒待たせる試験や所有者異常終了後の自動回復は未実施・非対応 |
| 中 | 保存メタデータの未終端文字列、不正なパス・表示文字・IDを利用してしまう | 読込み・移行時に検査し、不正データの起動・変換を拒否。破損データ3種、保存件数が設定上限を超える場合を実Apacheで確認 |
| 中 | フォームのNULを文字列終端として扱う、重複項目の解釈が曖昧、不正な文字コードが途中で切られる | テキストNUL・重複項目・変換失敗を拒否。バイナリファイル中のNULは許可。実HTTPと実パーサの変異入力で確認 |
| 中 | 欠落した本体ファイルのオープン結果を確認せず、未初期化ハンドルを使用する | オープン失敗をエラー処理。原本を意図的に欠落させ、エラー応答後も一覧を取得できることを確認 |
| 中 | エラー・リダイレクトHTMLの未エスケープ出力、長いIP文字列の切詰め・比較の不整合 | HTML特殊文字をエスケープ。アドレス長・終端を検査。エスケープの検査と既存HTTP回帰試験 |
| 中 | ダウンロード終了処理から例外が漏れる、上限超過時の5秒待機でワーカーを占有する | デストラクタ内で捕捉・記録し、待機を除去。正常系のHTTP回帰を確認。今回のDownloadSession後処理の実OS障害注入は未実施 |
| 中 | 共有メモリの64bit値が不適切な境界に置かれる。更新カウンタ等の排他も不足する | 自然なアラインメントを持つ構造体へ変更し、更新をロックで保護。実Apacheの並行要求・再起動試験。ThreadSanitizerや他ABIでは未検証 |
| 中 | 設定用APRプールがApacheの設定プールから独立し、モジュール解放後に後処理を呼んで停止時にクラッシュする | プールを設定プール配下に変更。FreeBSDのコアのバックトレースから調査。HTTP試験に停止終了コードの検査も追加 |

従来の画面・基本機能は維持しました。ただし、曖昧・不正な入力は拒否し、メール連携は認証を追加しないと使用できません。保護ファイルの公開サムネイルは表示しません。重複フォーム項目はCSRF検査より前に解析エラーとなり、既存のエラー画面方式によりHTTP 200を返します。正常な操作の成功を意味する応答ではなく、保存・削除は行いません。

## 検証結果

FreeBSD 15.1-RELEASE amd64 / Clang 19.1.7 / Apache 2.4.69 / OpenSSL 3.5.6。THUMBNAIL無効。検証記録は [security-audit](validation/security-audit/README.md) に収録します。

| 検証 | 結果・範囲 |
| --- | --- |
| Portのクリーンビルド・stage | 成功 |
| check-plist / stage-qa / package | すべて成功、`ap24-mod_uploader-3.2.0_5.pkg`を作成 |
| 既存C++試験 | safety 80,012、buffer 7、reader 7、origin 16、security 21、throttle 20チェック成功。reader等のAPR/httpdは代替実装 |
| 例外処理試験 | Locker 6、handler 5チェック成功。APR失敗戻り値・httpd APIを代替して検査 |
| データ移行 | 38チェック成功。旧形式、バックアップ、破損・リンク拒否、中断と復旧 |
| 実HTTP / HTTPS | HTTP 44、HTTPS 6チェック成功。CSRF、ハッシュ、取得・削除、再起動、バックアップ復元と旧モジュールでの取得 |
| 認証・試行制限 | 41チェック成功。実プロキシ、認証、共有IP枠・同時枠、並行要求、再起動 |
| 今回追加のHTTP | 20チェック成功。不正投稿時の既存データ保持、入力拒否、認可、欠落原本、破損データ、容量、並行投稿 |
| ASan + UBSan | 2,115チェック成功。実APR・実パーサ、2,000件の決定的な変異入力、一覧境界、ロック・世代比較・HTMLエスケープ |
| Clang Static Analyzer | 構成された43翻訳単位、解析時コンパイルエラー0。`MessageDigest5.cpp:92`の未使用代入警告1件。警告がないことを安全性の証明とは扱わない |

サニタイザ試験では一覧の正確な割当て境界を検査するため、APR共有メモリの基底アドレス取得をヒープ領域で代替しています。カーネルの共有メモリ自体のサニタイザ検査ではありません。実HTTPでは実際の共有メモリを使用しました。リーク検査は無効です。並行投稿試験では古い投稿間隔制限だけをテスト用設定で無効にしています。

途中の試験失敗も記録しています。重複トークンは早期の解析エラーへ変わったため、正しい削除パスワードでもファイルが残ることを検査するよう修正しました。起動拒否試験は、設定検査前の一時的なTCP受付を起動成功と誤判定していたため、プロセスのエラー終了を待つよう修正しました。その後に発見した停止時クラッシュは製品コードの修正対象とし、停止結果も確認します。

## 未検証事項・運用上の制約

- 本番環境へのインストール・本番データ移行・既存プロキシ設定の検査は実施していません。公開前に専用管理者認証、HTTPS、保存領域の非公開設定を適用してください。
- 全リクエスト形状、長期間のファジング、ThreadSanitizer、長時間高負荷、電源断・ディスク満杯・I/O故障時の完全なトランザクション回復、実OS/APR解除障害は検証していません。無効な入力による削除は防ぎましたが、有効投稿の保存中にI/Oが失敗した場合の完全な巻戻しは未実装です。
- 古いファイルの自動削除は元の仕様として残ります。有効な匿名投稿を繰り返せば保存上限到達時に古いファイルが消え得ます。ファイルを必ず保持したい運用では、投稿のアクセス制限と別系統のバックアップが必要です。
- THUMBNAIL有効時のImageMagick解析、delegate、許可形式・資源制限は未検証です。既定の無効状態を維持してください。保護サムネイルの拒否は模擬画像ファイルで確認しています。
- Apache/APR/OpenSSL/ImageMagick等の依存製品について、公開済み脆弱性を網羅した照合は今回実施していません。今回のソース監査だけで依存製品の安全性を保証しません。
- 他ABI、poudriere、実ブラウザの全画面、旧クライアント、メール投稿の認証付き正常系全体は未検証です。メール入口の認証拒否と境界条件は検査しています。
- 分散アクセス・通信量・一時領域枯渇・管理者Basic認証への総当たりは、公開側の制限も必要です。IP共有や固定窓方式の制約は[運用手順](SECURITY-MIGRATION-ja.md)を参照してください。
- 共有ロックの所有者が異常終了した場合、自動的にロックを奪って回復しません。原因調査とApacheの完全再起動が必要です。
- メタデータのMD5は旧来の内容識別に使用する値です。パスワード保存には使用しません。ハッシュ衝突耐性を必要とする署名・改ざん検出機構ではありません。

リビジョン3/4で形式4へ移行済みなら、今回の更新で再ハッシュは不要です。更新前にバックアップし、Apacheを完全停止して新モジュール・設定を適用してください。旧版へ戻す場合は、その版に対応するバックアップを戻します。詳細は[移行・復旧手順](SECURITY-MIGRATION-ja.md)を参照してください。
