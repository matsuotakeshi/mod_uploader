# VirtualHostルート配置の改修・検証報告

追記（2026-11-02）: 最初の配布ZIPにCRLFが入り、FreeBSDで`./configure`を起動できない問題が判明しました。前回のCRC・正規化ハッシュ照合では検出できませんでした。配布工程を修正し、ZIP展開後の直接ビルドと実HTTP試験を追加検証しました。[配布ZIPの修正報告](SOURCE-ARCHIVE-FIX-ja.md)を参照してください。

作業日: 2026-11-02。比較元は近代化済みリビジョン5の`10900e0fd9267994e48f3538090ea58e0a3b7320`、改修版はPortリビジョン6です。保存形式4、既存のパスワードハッシュ・CSRF・管理者認証・試行制限を維持します。本番モジュール・設定・データを交換せず、検証専用ディレクトリと127.0.0.1で待ち受ける別Apacheを使用しました。

## 根本原因と変更

従来はApacheの`path_info`をコマンド列として使用し、空のときにリクエストURIが`/`で終わると実ディレクトリとの衝突と判定していました。VirtualHostルートではDocumentRootが実ディレクトリなので、正しい`GET /`もエラーになりました。リビジョン5のモジュールでこの症状を再現しました。

リビジョン6は正規化したBaseUrlのパスと、Apacheが提供するデコード済みURIの境界を照合し、配置場所からの相対コマンドを取り出します。ルートの`/`は空コマンドとして既存の一覧処理へ渡します。`/up`の307リダイレクト、`/up/`・`/up/index`、サブパスの実ディレクトリ衝突検査は残します。URIを再デコードせず、空・ドット区間・バックスラッシュ・曖昧な符号化・配置パス境界の不一致を拒否します。

| ファイル | 主要な変更 |
| --- | --- |
| `include/UrlRouting.h`（新規） | BaseUrl末尾の正規化、配置パス境界、ルートとサブパスの共通解析、安全なパス検査 |
| `src/UploaderConfig.cpp` | 起動時のBaseUrl正規化・検査 |
| `src/uploader_handler.cpp` | 新しい相対ルート解析、空文字列・NULL防御、静的ファイル用`ASSET_BASE_URL`の提供 |
| `tmpl/*.htm.in`・`tmpl/en/*.htm.in`（11ファイル） | `BASE_URL/../up_*`を`ASSET_BASE_URL/up_*`へ変更。レイアウト・日本語文字コード・機能リンクは維持 |
| `src/GNUmakefile.in` | libtoolが拒否する`-L /usr/local/lib`を`-L/usr/local/lib`へ修正。ImageMagick有効の直接ビルドで確認 |
| `ports/www/mod_uploader/` | リビジョン6、ルート設定例・手順書の同梱、静的URLのdefault-handler指定、改修パッチの更新、pkg-plistの空行除去とLF統一 |

## 実機の検証範囲

FreeBSD 15.1-RELEASE amd64、Clang 19.1.7、Apache 2.4.69。環境の出力は[environment.log](validation/root-deployment/environment.log)に保存しています。

Portの既定構成はTHUMBNAIL無効です。別のビルドディレクトリで、検証機に既に入っていたImageMagick 6.9.13.50（Q16）を指定してサムネイルを有効にしました。実際のPNG投稿からGIF生成、一覧への画像URL出力、GIF本体の取得・寸法・MIME、原本の同一性を確認しました。ImageMagick 7への入替えや本番Apacheの再起動は行っていません。

新HTTP試験は次の7構成をそれぞれサムネイル無効・有効で検査しました。

| 配置 | BaseUrl末尾スラッシュ | 通信 |
| --- | --- | --- |
| `/` | あり・なし | HTTP |
| `/up` | あり・なし | HTTP |
| `/board/up` | あり | HTTP |
| `/` | あり | HTTPS |
| `/up` | あり | HTTPS |

各構成で`/`または`/up/`、`index`、`index/`、`rss/`、`thumbnail/`、アップロード・ダウンロード・削除を確認しました。生成URLにパス中の二重スラッシュや`/..`がないこと、静的画像/CSS/JavaScript/SWFの内容・MIME、ACME用静的ファイルの取得も確認しています。管理画面は未認証拒否、Basic認証とIP制限、認証後のCSRF必須を検査しました。内部データの直接取得、不正URL、保護サムネイルの取得も拒否されます。

HTTPSは検証専用の自己署名証明書をクライアントが信頼する構成で、証明書照合を無効化していません。Let's Encryptの実証明書ではありません。配布設定例の追加試験は、日本語テンプレートを使用し、サンプルの`Require local`と管理・メール閉鎖を維持しています。

単体試験の一部はAPR/httpdの代替実装を使用します。既存サニタイザ試験のリーク検査は無効で、共有領域の境界検査ではヒープ領域による代替も含みます。実HTTP試験は実Apache・実共有メモリを使用し、停止終了コードも確認します。既存監査の並行投稿試験では投稿間隔だけを検査用に無効にしています。新しい配置試験ではその変更をしていません。

初回の失敗もログに残しています。新しい試験環境の主ErrorLog位置と英語サムネイル画面の見出しの期待値を修正しました。ImageMagick有効時は上記のlibtool引数を修正しました。Portの最初の配置・package検査は、転送したpkg-plistのCRLFと空行で失敗したため、LF・空行なしに修正して再実行しました。これらの初回ログを最終成功ログと混同しないよう名前を区別しています。

実行ログ、ソース同一性の確認、パッケージ情報は[検証記録](validation/root-deployment/README.md)を参照してください。

## 未検証事項・既知の制約

- 本番へのモジュール交換、既存データでの切替、公開HTTPS、実際のリバースプロキシ、実ブラウザによる全画面・見た目の比較は未実施です。自動HTTPでHTMLと配信内容を検査しました。
- Certbotの発行・更新、DNS・実証明書チェーンは未検証です。ACME用パスの静的配信だけを検査しました。
- ImageMagick 7を使うTHUMBNAIL有効Portパッケージ、poudriere、別ABI/OS/Apache版は未検証です。作成したPortパッケージはTHUMBNAIL無効なので、サムネイル利用中の本番へそのまま導入しないでください。
- 実画像の確認は小さなPNGからGIFへの生成です。全画像形式、異常画像、delegate/policyの全構成、巨大画像の資源枯渇耐性、依存ライブラリの脆弱性網羅確認は行っていません。
- 基準URLのパスとLocationは一致し、プロキシもそのパスを保持する必要があります。曖昧な符号化・ドット区間を含むBaseUrlや、パスを書き換えるプロキシ構成は対象外です。
- 既存の独自テンプレートは静的URL部分の更新が必要です。変更前の画面にあるCSRFトークンは配置変更後に使えないため再読み込みします。
- 旧来のエラー画面がHTTP 200を返す箇所は残ります。エラー時のHTTP 200を操作成功と解釈しないでください。Flash実行・旧CGI/standalone・メール連携の全正常系は未検証です。
- 長時間負荷、OS/I/O故障時の完全な復旧、競合の網羅検査など、[前回監査の制約](SECURITY-AUDIT-ja.md)も残ります。今回の成功は「脆弱性がない」という保証ではありません。

## 適用と復旧

[ルート・サブパス配置手順](ROOT-DEPLOYMENT-ja.md)に完全な設定例を記載しました。モジュール・設定・テンプレート・保存データをバックアップし、既存のサムネイル設定を引き継いでビルドします。検証後に管理者が本番適用を判断し、Apache完全停止中に交換、設定検査後に起動します。失敗時は停止して旧モジュール・設定・テンプレートを戻します。保存形式4は変更していません。データ復元が必要なら切替後の追加データを退避して対応するバックアップを戻します。
